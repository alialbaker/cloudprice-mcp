# v0.18.2 — cap the `mcp` dependency, and split dispatch from the protocol

Two changes. The first fixes a bug that broke every fresh install. The second
is groundwork for running the same engine behind Amazon Bedrock AgentCore
Gateway.

---

## 1. `mcp>=1.0.0` was unbounded, and mcp 2.x broke the API

`pyproject.toml` declared:

```toml
"mcp>=1.0.0",
```

The MCP SDK released 2.x, which **removed `Server.list_tools`**. Because the
floor had no ceiling, a fresh install resolved to the newest release and the
package failed at import:

```
$ pip install cloudprice-mcp
$ cloudprice-mcp
AttributeError: 'Server' object has no attribute 'list_tools'
```

Existing environments were unaffected — they had 1.x already resolved — so
this was invisible locally while breaking **every new user**. That is the
worst shape a bug can have for a package whose whole distribution story is
PyPI, Glama and Smithery listings.

Fixed by capping the major version:

```toml
"mcp>=1.0.0,<2",
```

`server.py` targets the 1.x low-level `Server` API. Migrating to 2.x is a
separate piece of work; the cap makes the package correct in the meantime
rather than leaving it broken while that is scheduled.

**Lesson worth keeping:** an unbounded floor on a pre-1.0-culture dependency
is not a loose pin, it is an unowned upgrade. The test suite could not catch
this because nothing in `tests/` imports `server.py`.

---

## 2. New `cloudprice_mcp.dispatch` — the engine without the protocol

### Why

The tool implementations lived in `server.py`, which imports the MCP SDK at
module scope. Anything wanting to call a tool therefore had to install `mcp`
and, transitively, `starlette`, `uvicorn`, `sse-starlette` and
`pydantic-settings` — a web stack, to look up the price of an EC2 instance
from a bundled JSON file.

That mattered as soon as a second front end appeared. An AWS Lambda sitting
behind AgentCore Gateway speaks to Gateway, and *Gateway* speaks MCP; the
function itself never does. It was paying for a protocol it does not use.

### What changed

`dispatch.py` now holds the tool implementations and knows nothing about
MCP, transports or servers:

```python
from cloudprice_mcp import dispatch

dispatch.call("get_aws_price", {"instance_type": "t3.2xlarge"})
# -> {"cloud": "aws", "monthly_usd": 242.94, ...}   plain dict

dispatch.tool_names()   # -> the 25 tool names
dispatch.list_skus("aws")
```

The handlers are unchanged apart from what they return: `_ok()` and `_err()`
now pass plain data through instead of wrapping it in `TextContent`.

`server.py` keeps the MCP wiring — the `Server`, the 25 `Tool` schemas — and
adapts:

```python
@server.call_tool()
async def call_tool(name, arguments):
    result = dispatch.call(name, arguments)
    return [TextContent(type="text", text=json.dumps(result, indent=2))]
```

`_list_skus` moved down and became public `dispatch.list_skus`, because both
layers need it: the tool descriptions in `server.py` and `_lookup` here.

### Consequences

- **No behaviour change.** The stdio MCP server exposes the same 25 tools
  and returns the same values.
- **A caller can skip the MCP SDK entirely.** Verified by importing
  `dispatch` with `mcp` blocked on `sys.meta_path` — 25 tools, correct
  results.
- **No private coupling.** The Lambda calls `dispatch.call()`, a public API,
  rather than reaching into `server._TOOL_HANDLERS`.

## 3. `gateway_lambda/` — the AgentCore Gateway target

A Lambda handler that exposes these tools to AgentCore Gateway. Gateway's
convention, per the AWS samples: `event` is the flat arguments dict, and the
tool name arrives on `context.client_context.custom["bedrockAgentCoreToolName"]`
prefixed as `<target>___<tool>`.

The handler returns errors as `{"error": ...}` payloads instead of raising,
so a model reading the response can report what actually went wrong rather
than receiving an opaque failure.

`gateway_lambda/test_local.py` exercises it with a fake Lambda context and
needs no AWS.

Because the engine makes no network calls and reads no credentials, the
function's execution role needs CloudWatch Logs and nothing else.

# v0.19.0 — FOCUS Ingest: "Analyze your own cloud bill, locally"

**Goal:** Turn cloudprice-mcp from a *list-price* comparator into a tool that analyzes a user's **actual cloud spend** — by ingesting a FOCUS 1.x billing export. This is the enterprise value unlock, and it runs 100% locally (the bill file never leaves the machine — that's the headline selling point for healthcare/finance FinOps teams).

**Why now:** We already *export* FOCUS 1.3 (v0.18). Reversing it to *ingest* reuses existing schema knowledge. Anomaly detection (`finops/anomaly.py`) and commitment optimization (`finops/commitment.py`) already exist and get pointed at real data. Mostly wiring, ~1 week.

**Tool count:** 25 → **29**.

---

## Architecture / privacy stance
- **Local only.** Bill is read from a disk `file_path`. **No new network calls.** Document prominently: "Your billing data never leaves your machine."
- **CSV first.** FOCUS exports are CSV. Parse with stdlib `csv` — **no new hard deps.** Parquet support deferred (would need `pyarrow`; add later only if asked).
- New module: `src/cloudprice_mcp/finops/focus_ingest.py`.
- Reuse existing renderers in `export.py` (`to_markdown`/`to_json`/`to_text`) for all tool outputs, so format handling is free.

## FOCUS columns to parse (1.1–1.3 supersets; be lenient on optional)
Required-ish: `BilledCost`, `EffectiveCost`, `BillingPeriodStart/End`, `ChargePeriodStart/End`, `ServiceCategory`, `ServiceName`, `ProviderName`, `RegionId`/`RegionName`, `ResourceId`/`ResourceName`, `SkuId`, `PricingQuantity`, `PricingUnit`, `ChargeCategory`, `CommitmentDiscountId`/`CommitmentDiscountStatus`/`CommitmentDiscountCategory`.
Validate the file has the core cost + period + service columns; warn (don't crash) on missing optional ones. Mirror the column names already emitted in `focus_export.py::_focus_row`.

## New tools (4)
1. **`analyze_bill(file_path, group_by?, top_n?, format?)`**
   - Top cost drivers by ServiceCategory / ServiceName / RegionId (group_by).
   - Total BilledCost vs EffectiveCost (shows commitment/discount effect).
   - Month-over-month delta + biggest movers if the export spans >1 billing period.
   - Output via existing renderers.
2. **`find_commitment_gaps(file_path, format?)`**
   - Use `CommitmentDiscountStatus`/`Category` to split covered vs on-demand spend → real **coverage %** and $ left on the table.
   - Feed the on-demand compute portion into `finops/commitment.py::optimize_commitment` for RI/SP savings estimate.
3. **`detect_bill_anomalies(file_path, sensitivity?, format?)`**
   - Build per-service (or per-resource) cost-over-time series from ChargePeriod, reuse `finops/anomaly.py::detect_price_anomalies` (z-score + %-change, auto-selected by density).
   - Reframe headline from "SKU price anomaly" → "cost spike in your bill."
4. **`estimate_migration_from_bill(file_path, targets?, top_n?, format?)`**
   - Take top-N compute line items, map to workload requests, chain `finops/migration.py::assess_migration` → "moving these to cloud X ≈ $Y/yr."
